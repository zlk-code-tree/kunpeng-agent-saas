# 开发环境部署流程

## 适用范围

开发模式由 Docker 提供 PostgreSQL、Redis 和对象存储，Gin API、Worker 和 Vben 前端在宿主机运行。这种模式便于热更新和调试，不代表完整容器化生产部署。

## 第一步：启动基础设施

在仓库根目录执行：

```bash
make infra-up
```

等价命令：

```bash
docker compose -f deploy/compose.yaml up -d postgres redis objectstore
```

检查状态：

```bash
docker compose -f deploy/compose.yaml ps
```

预期三个服务均为 `healthy`：

- `deploy-postgres-1`
- `deploy-redis-1`
- `deploy-objectstore-1`

## 第二步：执行数据库迁移

```bash
make migrate
```

该命令按文件名顺序执行 `server/migrations/*.sql`。迁移使用 `ON_ERROR_STOP=1`，任一 SQL 失败时命令返回失败。

迁移结果检查：

```bash
docker compose -f deploy/compose.yaml exec -T postgres \
  psql -U gin_dify -d gin_dify -c '\dt'
```

## 第三步：准备后端环境变量

```bash
cp server/.env.example server/.env
```

把示例中的 JWT 和凭据加密密钥替换为至少 32 个字符的随机值。当前配置加载器读取进程环境变量，不会自动读取 `.env` 文件，因此启动时需要显式加载：

```bash
set -a
. server/.env
set +a
```

## 第四步：启动 Gin API

打开一个终端，在已加载环境变量的 Shell 中执行：

```bash
make api
```

API 默认监听 `http://127.0.0.1:8080`。检查：

```bash
curl http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/readyz
```

`healthz` 表示进程存活，`readyz` 还会检查 PostgreSQL 和 Redis。

## 第五步：启动 Worker

打开另一个已加载相同环境变量的终端：

```bash
make worker
```

Worker 必须与 API 使用相同数据库、Redis、`APP_MODE` 和 `CREDENTIAL_ENCRYPTION_KEY`。

## 第六步：启动前端

首次运行：

```bash
make web-install
```

启动 Element Plus 版本前端：

```bash
make web-dev
```

前端默认开发地址以终端输出为准。当前后端示例允许的跨域地址是 `http://localhost:5777`，如果实际前端端口不同，必须同步修改 `CORS_ORIGINS`。

## 第七步：首次安装

打开前端后进入 `/install`，填写：

- 平台名称
- 默认租户名称
- 管理员用户名
- 管理员显示名称
- 管理员密码

安装操作会创建默认租户、管理员、成员关系、计费账户和预置智能体。安装只能成功执行一次。

## 停止开发基础设施

```bash
make infra-down
```

该命令不会删除持久化卷。不要为了重启而增加 `-v`。
