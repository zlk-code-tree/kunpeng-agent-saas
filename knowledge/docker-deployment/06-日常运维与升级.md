# 日常运维与升级

## 统一 Compose 参数

生产命令都应使用相同的项目配置组合：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml
```

如果某次命令漏掉 `compose.prod.yaml`，看到的只会是基础设施；如果漏掉 `compose.yaml`，应用依赖的 PostgreSQL、Redis 和对象存储将不存在。

## 查看状态

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  ps -a
```

生产环境预期服务：

- `postgres`
- `redis`
- `objectstore`
- `api`
- `worker`
- `web`

## 查看日志

查看最近 200 行：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs --tail=200 api worker
```

持续跟踪：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs -f api worker
```

## 健康检查

- `/healthz`：只确认 API HTTP 进程存活。
- `/readyz`：检查 PostgreSQL 和 Redis 是否可用。
- `/metrics`：输出当前 API 进程的 Prometheus 文本指标。

生产 Web 容器代理 `/healthz`，可以从外部入口验证：

```bash
curl -f https://平台域名/healthz
```

## 安全重启

只重启应用进程：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  restart api worker web
```

该操作不会删除数据卷。

## 升级顺序

1. 阅读版本变更和迁移说明。
2. 执行数据库与对象存储备份。
3. 构建新镜像。
4. 执行新数据库迁移。
5. 重建 API、Worker 和 Web。
6. 检查健康状态和日志。
7. 验证登录、智能体列表、知识库上传和一次完整运行。

构建命令：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  build api worker web
```

## 单租户升级为多租户

首先在与生产环境相同配置下执行预检：

```bash
cd server
APP_MODE=multi go run ./cmd/migrate-mode --to multi
```

确认报告后再使用 `--apply`。模式迁移会修改业务数据和安装配置，执行前必须备份。完成后把部署配置的 `APP_MODE` 改为 `multi`，再重启 API 和 Worker。

## 不应执行的常规操作

- 不要使用 `docker compose down -v` 重启。
- 不要直接删除 PostgreSQL、Redis 或对象存储 Volume。
- 不要在没有备份时运行恢复脚本。
- 不要直接替换 `CREDENTIAL_ENCRYPTION_KEY`。
- 不要在生产环境使用示例密钥。
