# Docker 部署故障排查

## 标准排查顺序

1. `docker compose ps -a` 查看容器状态。
2. 检查健康状态和退出码。
3. `docker compose logs --tail=200 服务名` 查看日志。
4. 从故障容器内验证服务名 DNS 和端口。
5. 核对环境变量、租户模式和密钥。
6. 核对数据库迁移是否完成。

不要一开始就删除容器或数据卷。

## API 容器不断重启

常见原因：

- 数据库迁移未执行，`installation_settings` 表不存在。
- `DATABASE_URL` 错误地使用了 `127.0.0.1:15432`。
- `JWT_SECRET` 少于 32 个字符。
- `CREDENTIAL_ENCRYPTION_KEY` 少于 32 个字符。
- `APP_MODE` 与数据库安装模式不一致。
- PostgreSQL 尚未健康。

检查：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs --tail=200 api
```

## API healthy，但页面打不开

检查 Web：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  ps web

docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs --tail=200 web
```

确认 `WEB_PORT` 未被其他 Nginx、Apache 或容器占用。若前面还有反向代理，检查其上游是否指向 Web 容器的宿主机端口。

## 登录或接口出现 CORS 错误

确认 `CORS_ORIGINS` 与浏览器地址栏中的协议、域名和端口完全一致。修改后需要重新创建 API 容器：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  up -d --force-recreate api
```

## Worker 不处理任务

检查：

- Worker 是否运行。
- API 和 Worker 的 `REDIS_ADDR` 是否相同。
- Redis 是否 healthy。
- Worker 是否使用相同数据库。
- Dify 实例是否 healthy。
- 智能体版本是否已绑定 Dify 应用。

日志命令：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs --tail=300 worker redis
```

## 智能体显示“等待绑定 Dify”

这不是前端故障，表示当前租户没有该智能体版本的有效 Dify 应用绑定。需要平台管理员：

1. 注册可用 Dify 实例。
2. 在 Dify 创建应用并取得应用 API Key。
3. 将应用绑定到对应 `agentVersionId`。

## 知识库一直处于 provisioning

表示本地知识库记录已创建，但没有成功创建上游 Dify Dataset。检查：

- 是否注册了当前租户可见的 Dify 实例。
- Dify 实例是否为 active。
- Base URL 是否能从 API 容器访问。
- 知识库 API Key 是否具备 Dataset 权限。
- `CREDENTIAL_ENCRYPTION_KEY` 是否正确。

## 文档一直处于 waiting

文档可能已经保存到对象存储，但未成功提交 Dify 索引。检查对象存储、Dify Dataset ID、Dify 凭据和网络。当前版本保留 waiting 状态以避免丢失本地文件，不代表已经可以被智能体检索。

## 对象存储上传失败

从 API 容器测试 Endpoint：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  exec api wget -q -O - http://objectstore:8333/healthz
```

还要检查 S3 Access Key、Secret Key、Bucket、SSL 配置和对象存储卷权限。

## 当前只看到三个 deploy 容器

如果只看到 `postgres`、`redis`、`objectstore`，说明执行的是基础 `deploy/compose.yaml`，并没有启动完整应用。生产环境需要同时使用 `deploy/compose.prod.yaml` 并启动 `api`、`worker`、`web`。
