# 部署前检查

## 执行目录

除非命令另有说明，所有命令都应在项目仓库根目录执行，也就是包含 `Makefile`、`deploy/`、`server/` 和 `web/` 的目录。

## 软件要求

部署机器需要：

- Docker Engine 或 Docker Desktop。
- Docker Compose v2 插件，即命令形式为 `docker compose`。
- 生产镜像构建需要能够拉取 Go、Node、Alpine 和 Nginx 基础镜像。
- 执行备份脚本需要 POSIX Shell、`shasum` 和足够的备份磁盘空间。

检查命令：

```bash
docker version
docker compose version
docker info
```

三个命令都应成功，`docker info` 应显示 Docker Engine 正在运行。

## 端口检查

部署前确认以下宿主机端口没有被占用：

```bash
lsof -nP -iTCP:15432 -sTCP:LISTEN
lsof -nP -iTCP:16379 -sTCP:LISTEN
lsof -nP -iTCP:18333 -sTCP:LISTEN
lsof -nP -iTCP:80 -sTCP:LISTEN
```

若端口已被其他服务占用，应修改 Compose 映射或停止冲突服务。不要直接停止用途未知的生产进程。

## 配置文件准备

生产部署先创建本地配置：

```bash
cp deploy/.env.prod.example deploy/.env.prod
```

至少替换：

- `JWT_SECRET`
- `CREDENTIAL_ENCRYPTION_KEY`
- `S3_SECRET_KEY`
- `CORS_ORIGINS`
- `APP_MODE`

生成随机密钥示例：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

三次输出分别用于 JWT、凭据加密和对象存储。不要复用同一个密钥，也不要把 `deploy/.env.prod` 提交到 Git。

## 租户模式选择

`APP_MODE` 只能是：

- `single`：单租户或单用户私有部署。
- `multi`：SaaS、集团或多组织部署。

首次安装后，数据库会保存安装模式。后续启动配置必须与数据库一致，否则 API 和 Worker 会拒绝启动。单租户升级到多租户必须先执行项目提供的模式迁移工具。

## 数据目录与备份目录

Docker Compose 默认使用命名卷持久化数据。正式部署前还应准备一个不在 Docker Volume 内的绝对备份目录，例如：

```bash
sudo mkdir -p /data/backups/gin-dify-saas
```

备份目录应具有足够空间，并纳入客户自己的异地备份策略。

## 外部 Dify 连通性

使用平台托管 Dify 时，客户侧 API 和 Worker 所在网络必须能够通过 HTTPS 访问 Dify API。建议提前验证 DNS、证书和防火墙，不要使用浏览器能访问作为容器也能访问的依据。

可在临时容器内验证：

```bash
docker run --rm curlimages/curl:latest -I https://DIFY_HOST/
```

该命令只验证网络和 TLS，不验证 Dify API Key。
