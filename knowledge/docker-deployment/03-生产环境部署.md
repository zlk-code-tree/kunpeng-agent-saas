# 生产环境完整部署流程

## 部署目标

生产环境使用 Docker Compose 同时运行：

```text
web + api + worker + postgres + redis + objectstore
```

Dify 可使用平台托管服务或客户私有实例，不在当前项目 Compose 文件内。

## 第一步：准备配置

```bash
cp deploy/.env.prod.example deploy/.env.prod
```

编辑 `deploy/.env.prod`，设置真实随机密钥、访问域名和租户模式。生产数据库连接应使用 Compose 服务名：

```env
DATABASE_URL=postgres://gin_dify:gin_dify@postgres:5432/gin_dify?sslmode=disable
```

容器间不能使用 `127.0.0.1:15432` 访问 PostgreSQL，因为容器内的 `127.0.0.1` 指向容器自身。

## 第二步：验证 Compose 配置

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  config --quiet
```

命令没有输出且退出码为 0 表示 YAML 和必填环境变量校验通过。

## 第三步：启动基础设施

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  up -d postgres redis objectstore
```

等待状态变为 `healthy`：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  ps
```

## 第四步：执行数据库迁移

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  exec -T postgres sh -c \
  'for migration in /migrations/*.sql; do echo "applying $migration"; psql -v ON_ERROR_STOP=1 -U gin_dify -d gin_dify -f "$migration"; done'
```

必须在首次启动 API 前完成迁移，否则 API 查询安装表时会启动失败。

## 第五步：构建并启动应用

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  up -d --build api worker web
```

构建内容：

- `server/Dockerfile` 编译 `api` 和 `worker` 两个 Go 二进制。
- `web/Dockerfile` 使用 Node 构建 Element Plus 前端，再复制到 Nginx 镜像。
- Web Nginx 将 `/api/`、`/healthz` 代理到 `api:8080`。

## 第六步：验证部署

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  ps
```

然后检查：

```bash
curl -f http://127.0.0.1:${WEB_PORT:-80}/healthz
```

查看最近日志：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  logs --tail=200 api worker web
```

## 第七步：完成平台首次安装

浏览器访问部署地址。未安装时前端会跳转到 `/install`。首次安装完成后使用管理员账号登录。

## 第八步：配置 Dify

使用平台托管 Dify 时，在平台管理界面完成：

1. 创建 Dify 实例，地址使用外部可达的 `/v1` API 基址。
2. 配置 Dify 知识库 API 凭据。
3. 在 Dify 创建“Docker 部署助手”应用并配置知识检索。
4. 使用应用 API Key 将 Dify 应用绑定到 Docker 部署助手版本。
5. 创建部署知识库并上传 `knowledge/docker-deployment/*.md`。

## 更新应用镜像

代码更新后执行：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  build api worker web
```

先完成备份和数据库迁移，再执行：

```bash
docker compose \
  --env-file deploy/.env.prod \
  -f deploy/compose.yaml \
  -f deploy/compose.prod.yaml \
  up -d api worker web
```
