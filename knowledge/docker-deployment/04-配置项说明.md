# 配置项说明

## 应用配置

| 变量 | 示例 | 说明 |
|---|---|---|
| `APP_ENV` | `production` | 运行环境；生产环境会启用 Gin ReleaseMode |
| `APP_MODE` | `single` | 租户模式，只允许 `single` 或 `multi` |
| `HTTP_ADDR` | `:8080` | Gin API 监听地址 |
| `DATABASE_URL` | `postgres://...@postgres:5432/gin_dify?sslmode=disable` | PostgreSQL 连接串 |
| `REDIS_ADDR` | `redis:6379` | Redis 地址 |
| `REDIS_PASSWORD` | 空 | Redis 密码，当前 Compose Redis 默认无密码 |
| `REDIS_DB` | `0` | Redis 数据库编号 |
| `JWT_SECRET` | 随机字符串 | JWT HS256 密钥，至少 32 个字符 |
| `JWT_TTL` | `2h` | 访问令牌有效时间 |
| `CREDENTIAL_ENCRYPTION_KEY` | 随机字符串 | 加密 Dify、模型和工具凭据，至少 32 个字符 |
| `CORS_ORIGINS` | `https://agent.example.com` | 允许携带凭据访问 API 的前端来源，多个值用逗号分隔 |
| `DIFY_TIMEOUT` | `120s` | Gin/Worker 调用 Dify 的超时 |
| `S3_ENDPOINT` | `http://objectstore:8333` | S3 兼容对象存储地址 |
| `S3_ACCESS_KEY` | `gin-dify` | 对象存储 Access Key |
| `S3_SECRET_KEY` | 随机字符串 | 对象存储 Secret Key |
| `S3_BUCKET` | `gin-dify` | 知识库文件存储桶 |
| `S3_USE_SSL` | `false` | 对象存储是否使用 TLS |

## 开发地址与容器地址的区别

在宿主机运行 Gin 时使用宿主机映射端口：

```env
DATABASE_URL=postgres://gin_dify:gin_dify@127.0.0.1:15432/gin_dify?sslmode=disable
REDIS_ADDR=127.0.0.1:16379
S3_ENDPOINT=http://127.0.0.1:18333
```

在 Compose 容器中运行 Gin 时使用服务名和容器端口：

```env
DATABASE_URL=postgres://gin_dify:gin_dify@postgres:5432/gin_dify?sslmode=disable
REDIS_ADDR=redis:6379
S3_ENDPOINT=http://objectstore:8333
```

这是部署故障中最常见的配置差异之一。

## 密钥管理

以下值不能写入源码、镜像或知识库：

- JWT 密钥
- 凭据加密密钥
- 数据库密码
- S3 Secret Key
- Dify API Key
- 模型供应商 API Key

生产环境应使用受限制的环境文件、Docker Secret 或客户现有密钥管理系统。配置文件权限建议至少限制为仅部署账号可读。

`CREDENTIAL_ENCRYPTION_KEY` 不能随意更换。数据库中的 Dify、模型和工具凭据使用它加密；直接换值会导致历史密文无法解密。密钥轮换必须提供专用的解密再加密流程。

## CORS 配置

`CORS_ORIGINS` 必须是浏览器实际访问前端时的 Origin，例如：

```env
CORS_ORIGINS=https://agent.example.com
```

Origin 包含协议和端口，不包含路径。错误示例：

```env
CORS_ORIGINS=agent.example.com/api
```

## 单租户和多租户

首次安装后，`installation_settings.mode` 会保存模式。若数据库是 `multi`，进程配置为 `single`，API 和 Worker 会拒绝启动。模式不一致不是健康检查偶发失败，应先修正配置或执行正式模式迁移。

## 对象存储

对象存储桶在第一次上传文档时由 API 延迟创建。API 需要具备检查和创建存储桶的权限。上传失败时应检查：

- Endpoint 是否可从 API 容器访问。
- Access Key 和 Secret Key 是否正确。
- Bucket 名称是否合法。
- 对象存储卷是否可写。
- 是否错误配置了 `S3_USE_SSL`。
